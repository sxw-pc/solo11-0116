# 契约转译台

旧版 JSON 接口封套转新业务消费者契约。保留版本、字段级来源、身份冲突、缺失语义、错误映射和跨包状态证据。

运行：`python -m pip install . --no-deps --no-build-isolation`，`python -m contractbridge demo`，`python -m contractbridge --help`，`python -m pytest -q`。运行与测试使用本地合成数据，不访问网络。

## 转译依赖与独立验真

`chain` 映射可用 `$目标字段名` 引用另一已转译字段；规则按依赖排序，未知引用和循环在契约冻结时拒绝。跨包状态按 UTC 瞬时排序，避免时区偏移改变业务次序。`verify` 从原始封套重放转译并重算字段级来源，能发现输出值及其哈希被一起改写、或证据指针被伪造。

同一契约版本号对应的规则正文不可更改；语义变更必须分配新版本，旧版本保持可复核。

## 消费者配额与交付回执

`consumer-policy` 冻结消费者额度，`allocate` 根据逐条验真、主体去重及累计金额形成配额决定。`dispatch` 只对整批已配额输出生成交付快照；`acknowledge` 逐条记录接收或失败，重复回执幂等，冲突回执拒绝。转译已核验但额度超限时暂缓交付；部分接收失败形成可查询的部分失败状态。

`migration-plan` 定义旧新契约的金额漂移预算，`migration-compare` 对同一原始封套的双份转译逐项复验身份、业务状态和金额，保存差异记录。目标契约的交付会重算迁移结论；单条语义漂移、缺失或篡改分别阻断或暂缓切换，即使目标转译单独验真通过也不直接交付。

## 跨接口交易状态守恒

契约可声明冻结的 `transaction` 段：协议（`preauth` 预授权或 `direct_debit` 直接扣款）、交易 ID 来源指针（支持多指针歧义检测）、规范事件字段、业务时刻、金额、幂等事件键与直接扣款凭据字段。`translate` 产出的规范交易事件按业务时刻重建授权、扣款、退款与撤销状态链，结论写入独立的 `transaction_record`、`transaction_event` 与 `transaction_gap` 表；逐实体 `reconcile` 与既有 output 不被改写。

守恒规则：扣款不得超过授权（直接扣款允许无授权事件，但扣款响应必须携带不可重用凭据）；退款不得超过已扣减已退余额；同一业务事件键的精确重放幂等不重复记账，载荷冲突的重放判 `replay_conflict`；凭据跨交易或同交易重用两协议均不放行；缺必要接口、交易 ID 缺失或歧义、乱序无法收敛、任一 output 未通过 verify 时，交易结论为 `待核` 并在缺口表指出具体代码。协议冻结在契约哈希内，看到事件缺口也不会自动切换。晚到退款按业务时刻追加到事件链，可退余额随证据更新而历史事件全部保留。

`transactions` CLI 子命令返回逐笔核对结论；`report` 的 JSON 与 Markdown 展示每笔交易的余额、按业务时刻排序的事件引用（源哈希、封套、output、事件键、重放次数）与缺口。`migration-compare` 在逐封套 id/status/amount 比较之外，因果性地接入交易结论：目标侧任何 output 属于不守恒交易时，cohort 判 `待核 / transaction_unconserved`，表面合法的 JSON 不会被合并成可切换交易。
